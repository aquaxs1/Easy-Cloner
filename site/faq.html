Frequently asked questions

The things people actually ask — and the errors they actually hit.

General

It reads the complete structure of one Discord server — roles with their exact permissions, categories, channels, per-channel overrides, emojis, stickers, server settings — and rebuilds all of it on another server. It can also save that structure to a file and rebuild from the file later.

It does not move members, messages or bots. Those are not things the Discord API allows anyone to copy.

Free and MIT licensed. There is no hosted version and that is deliberate: a tool with Administrator rights on your server should run on hardware you control, with a token only you hold.

Nowhere. The bot talks to Discord and to nothing else. Backups and checkpoints are written to the backups/ and state/ folders on your own machine, and both are git-ignored.

This website is static and carries no analytics, no cookies and no trackers.

Copying your own servers — for backups, staging or templates — is ordinary bot behaviour and what this tool is built for. The bot needs Administrator on both sides, so it can only ever touch servers you were granted access to.

Copying someone else's server without permission is a different matter, and the Terms of Use ask you not to. Discord's own Terms of Service apply either way.

Roughly one second per object, so a 40-channel server with 20 roles and 50 emojis lands somewhere around two minutes. /preview gives you an estimate before you commit.

Discord's rate limits set the floor here. Turning CLONE_DELAY down usually makes things slower, not faster, because you spend the time waiting out 429s instead.

Using it

Discord only lets a bot grant permissions it holds itself. To recreate a role that can ban members, the bot must be able to ban members. With a narrower permission set, your roles would arrive stripped of exactly the permissions you cared about.

The bot does handle the refusal gracefully — a role it cannot fully recreate is created without permissions rather than skipped — but the result needs fixing by hand afterwards.

Yes, and you have three ways to do it:

  • /clone — clears the target first, then rebuilds. An exact copy.
  • /clone wipe_target:False — adds on top without deleting.
  • /sync — adds only what is missing, reuses same-named objects, leaves settings alone.

Run /preview first either way. It tells you exactly how many channels and roles would be deleted.

It can rebuild them, which is not the same thing. /clone messages:100 replays the last 100 messages per channel through a webhook using each author's name and avatar. They look right, but they are new messages posted by a webhook — reactions, threads, pins and edit history do not come along.

No, and neither can anything else. Discord has no API for moving a user into a server — people have to accept an invite themselves. Any tool claiming otherwise is either lying or breaking the rules.

What it can do: once people have joined, /clone member_roles:True gives everyone who is on both servers the same roles in the new one.

Emojis and stickers are what make backups big. Use /backup include_images:False for a structure-only file — usually a few dozen kilobytes.

The full version is still written to the backups/ folder next to the bot, so nothing is lost. You just cannot hand it over through Discord.

Troubleshooting

Global commands take up to an hour to propagate. To get them immediately, set DEV_GUILD_ID in your .env to the server you are testing on and restart.

Also check the bot was invited with the applications.commands scope, not just bot. If it was not, re-run the invite link.

Discord rejected the token. Either it is mistyped, or it was reset since you copied it — pressing Reset Token invalidates the old one immediately.

Generate a fresh one in the Developer Portal and paste it into .env. Watch for stray spaces or quotes around the value.

You set ENABLE_MESSAGE_CLONE or ENABLE_MEMBER_ROLES to true, but the matching intent is still switched off in the Developer Portal. Discord then refuses the login outright.

Either enable the intent under Bot → Privileged Gateway Intents, or set the variable back to false. The two always move together.

The bot's role on the target server does not have Administrator. Go to Server Settings → Roles, open the bot's role and switch it on.

The check runs before anything is deleted, so nothing has happened yet.

The bot's own role was sitting too low. Discord never allows a bot to create a role above its own, so everything it makes lands underneath — and if the bot is near the bottom, that leaves no room for a hierarchy.

Drag the bot's role to the top of the list in Server Settings → Roles and clone again. The bot warns you about this up front when it spots the problem.

Both only exist on Community servers. Enable Community in Server Settings → Enable Community on the target, then run /sync to add what was skipped.

The same applies to announcement channels — on a non-Community server they are created as normal text channels, and the report tells you so.

Server banners need Boost level 2. The bot notices the rejection, warns you and carries on with everything else rather than aborting the run.

Nothing is lost. Run /clone resume:True and it continues from the checkpoint — skipping what already exists, recreating anything that vanished, and never wiping the target a second time.

/status shows you what is waiting. Checkpoints expire after 24 hours.

Normal on large servers. The bot detects the slowdown, widens the pause between calls automatically and narrows it again once things settle. Nothing to do — just let it run.

On macOS and Linux the command is python3. On Windows, this usually means Python was installed without “Add Python to PATH” — the quickest fix is to reinstall and tick that box.
